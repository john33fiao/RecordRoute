## 2) 핵심 결론

1. **백엔드 핵심 워크플로우는 완료 상태**다. 업로드/처리/진행조회/검색/유사도 API까지 운영 가능한 수준이다.
2. **프론트는 React 전환이 완료**됐고, 레거시(`frontend/legacy/*`) 기준 항목은 별도 트랙으로 분리해야 한다.
3. **Graph는 미착수가 아니라 MVP 부분완료**다. 계산 모듈 + API + 정적 뷰가 이미 존재한다.
4. 다음 스프린트는 “문서상 미완료”가 아니라 **실제 실행 가능한 P0/P1 백로그** 중심으로 재편했다.

## 3) 레거시 vs React 분리 원칙 적용

- **레거시 트랙(유지보수만):** `upload.js` 모듈화/정리 등은 P2로 격리
- **React 트랙(유효 백로그):** `frontend/src/*` 기준의 진행률 UX, 접근성, 검색 고급화, 상태관리 최적화만 유지

## 4) 다음 스프린트 즉시 실행 백로그

### P0
1. `handler.py` 책임 분리(라우트 단위 모듈화)
2. 파괴적 API 보호(`/shutdown`, `/delete*`, `/reset*`)
3. 그래프 렌더 엔진 확정 + 줌/팬/드래그 MVP
4. 큐 진행률(%) 및 ETA 표시 + 오류카드 표준화

### P1
1. 검색 고급필터 UI + 하이라이트
2. 오버레이 접근성(ESC/포커스 트랩/ARIA)
3. 그래프 스타일/필터 + React 메인 UI 통합
4. 테마 영속화(localStorage + 시스템 테마)

### P2
1. 컨텍스트 리렌더 최적화
2. 대용량 히스토리 가상 스크롤
3. 그래프 증분 업데이트 전략
4. 레거시 코드 정리

## 5) 의존관계 맵 (실행 전 체크)

- 에러/진행률 UX(P0) ← 백엔드 progress/오류 DTO 표준화
- 검색 고급화(P1) ← 검색 API 계약(파라미터/응답) 명세
- 그래프 통합(P1) ← 렌더 엔진 확정(P0)
- 운영 지표(P2) ← 로깅/메트릭 스키마 정리

## 6) 상태값 정리 결과

- 문서 전반의 “전부 미착수” 표기를 제거하고 `완료/부분완료/미착수`로 재분류했다.
- 레거시 기준 항목과 React 기준 항목을 분리하여 **유효한 백로그만 남겼다**.
- 모든 실행 항목에 우선순위(P0/P1/P2)와 의존관계를 명시했다.
