# RecordRoute 최종 사용자 조작 매뉴얼

## 요약

RecordRoute는 클라우드 API에 의존하지 않고 로컬 환경에서 AI 모델(Whisper, Llama.cpp 계열)을 직접 구동하는 음성/텍스트 처리 시스템입니다.
사용자는 모델 파일을 사전에 준비한 뒤 웹 UI에서 업로드, 큐 모니터링, 결과 조회, 검색/그래프 탐색, 설정 변경을 수행합니다.

## 핵심 기능

1. 사전 준비: Hugging Face에서 모델 파일 다운로드 및 로컬 배치.
2. 파일 업로드 및 작업 생성: UploadSection에서 Job 생성 후 Queue 상태 확인.
3. 처리 결과 및 검색: History/Search/Similarity Graph로 결과 검증 및 탐색.
4. 시스템 및 UI 설정: SettingsDialog에서 STT/LLM/임베딩 모델 매핑, 다크 모드, 종료 제어.

## 1. [사전 준비] Hugging Face에서 로컬 모델 다운로드 및 배치

### 기능 개요

로컬 모델 준비는 RecordRoute 운영의 필수 전제입니다.
이 절차를 통해 데이터가 외부 클라우드 API로 전송되지 않으며, 내부 보안 정책과 데이터 주권 요구를 충족할 수 있습니다.

### 왜 필요한가

- 오디오/텍스트 원문이 로컬 서버에서 처리되어 외부 전송 리스크를 줄입니다.
- 네트워크 장애 또는 외부 API 정책 변경에 영향을 덜 받습니다.
- 조직 내부 승인된 모델 버전을 고정해 재현성과 감사 가능성을 확보합니다.

### 1-1. Whisper(STT) 모델 다운로드 단계

1. 브라우저에서 Hugging Face에 접속합니다.
2. 검색창에 `whisper ggml` 또는 `whisper.cpp model`을 입력합니다.
3. RecordRoute 배포 문서에서 허용한 모델 저장소를 확인한 뒤, 해당 저장소 Releases/Files 탭을 엽니다.
4. `.bin` 형식(또는 현재 배포가 요구하는 호환 형식)의 STT 모델 파일을 선택해 다운로드합니다.
5. 다운로드 파일명에 모델 규모가 포함되어 있는지 확인합니다(예: `base`, `medium`, `large`, `large-v3-turbo`).

### 1-2. Llama.cpp(요약/임베딩) 모델 다운로드 단계

1. Hugging Face 검색창에 `gguf instruct`, `gguf embedding` 또는 조직 표준 모델명을 입력합니다.
2. 파일 목록에서 `.gguf` 확장자를 가진 파일만 필터링합니다.
3. 목적에 맞게 모델을 분리해 선택합니다.
   - 요약용: 지시(instruct/chat) 튜닝 모델
   - 임베딩용: embedding 전용 모델
4. 양자화(Quantization) 레벨을 선택해 다운로드합니다.

### 1-3. 양자화(Quantization) 선택 가이드

| 양자화 예시 | 속도 | 정확도 | RAM 요구량 | 권장 환경 |
| --- | --- | --- | --- | --- |
| `Q4_K_M` | 빠름 | 중간 | 낮음 | 일반 노트북/메모리 제약 환경 |
| `Q5_K_M` | 중간 | 중상 | 중간 | 균형형 기본 선택 |
| `Q8_0` | 느림~중간 | 높음 | 높음 | 고사양 워크스테이션/정확도 우선 |

권장 기준:
- 메모리 16GB 이하: `Q4_K_M` 우선 검토.
- 메모리 32GB 전후: `Q5_K_M` 기본, 품질 요구 높으면 `Q8_0` 시험 적용.
- 동일 프롬프트로 3회 이상 결과를 비교해 지연시간과 품질을 함께 평가합니다.

### 1-4. 모델 파일 배치 단계

RecordRoute 표준 경로 예시는 다음과 같습니다.

- STT(Whisper): `models/stt/`
- 요약(Text/LLM): `models/text/`
- 임베딩(Embed): `models/embed/`

실행 단계:

1. 프로젝트 루트에서 `models/` 하위 구조를 확인합니다.
2. 다운로드한 모델 파일을 목적별 디렉토리로 이동합니다.
3. 파일 권한(읽기 가능)과 파일 크기(손상 여부)를 확인합니다.
4. 기존 manifest 기반 운영 환경이면 모델 메타데이터를 배포 규칙에 맞게 갱신합니다.

### 1-5. 시스템 인식 검증 단계

1. RecordRoute 서버를 실행한 뒤 웹 UI에 접속합니다.
2. SettingsDialog를 열어 모델 선택 목록에 방금 배치한 모델이 노출되는지 확인합니다.
3. 해당 모델을 지정하고 짧은 샘플 작업을 1회 실행합니다.
4. 작업 상태가 `completed`로 종료되고 결과 텍스트/요약이 생성되는지 확인합니다.

### 주의사항 및 검증 방법

- 다운로드 출처가 불분명한 모델 파일은 사용하지 않습니다.
- 동일 이름의 구버전 파일이 남아 있으면 잘못 매핑될 수 있으므로 버전명을 파일명에 유지합니다.
- 검증 기준:
  - 모델 목록 노출 + 작업 1회 성공 + 결과 생성이 모두 확인되어야 합니다.

## 2. 파일 업로드 및 작업 생성 (UploadSection)

### 기능 개요

UploadSection에서 오디오 또는 텍스트 파일을 업로드하고 처리 작업(Job)을 생성합니다.
생성된 작업은 Queue를 통해 `queued` → `running` → `completed|failed|timeout|canceled|rejected` 상태로 전이합니다.

### 세부 조작 단계 (Step-by-step)

1. 메인 화면의 **UploadSection**으로 이동합니다.
2. **파일 선택** 버튼을 클릭해 입력 파일(오디오/텍스트)을 선택합니다.
3. 파일명, 유형, 작업 목적을 확인합니다.
4. **작업 생성** 버튼을 클릭합니다.
5. JobQueue에서 신규 작업이 생성되고 상태가 `queued` 또는 `running`인지 확인합니다.

### 주의사항 및 검증 방법

- 대용량 파일 업로드 중 브라우저를 종료하지 않습니다.
- 실패 상태 발생 시 재시도 전에 모델 매핑/입력 파일 손상 여부를 먼저 점검합니다.
- 검증 기준:
  - JobQueue 항목 생성 여부.
  - 상태 전이 진행 여부.

## 3. 처리 결과 및 검색 (History & Search)

### 기능 개요

HistoryPanel/HistoryListItem에서 완료 결과를 확인하고, SearchPanel/SimilarityGraphPanel로 연관 문서를 탐색합니다.

### 세부 조작 단계 (Step-by-step)

1. **HistoryPanel**에서 `completed` 작업을 선택합니다.
2. **HistoryListItem** 상세에서 전사 텍스트와 요약 결과를 확인합니다.
3. **SearchPanel**에 질의어를 입력하고 검색을 실행합니다.
4. 검색 결과 문서를 클릭해 상세를 확인합니다.
5. **SimilarityGraphPanel**에서 노드를 클릭하여 연관 문서로 이동합니다.
6. 이동한 문서의 요약/본문을 비교해 탐색을 반복합니다.

### 주의사항 및 검증 방법

- `completed` 이전 상태의 결과는 불완전할 수 있습니다.
- 검색 품질은 질의 문장 길이와 모델 선택에 따라 달라집니다.
- 검증 기준:
  - 히스토리 상세와 선택 항목 일치.
  - 그래프 노드 클릭 시 연관 문서 뷰 갱신.

## 4. 시스템 및 웹 UI 설정 (SettingsDialog)

### 기능 개요

SettingsDialog에서 STT 모델, LLM Provider, 요약/임베딩 모델 매핑, 테마, 시스템 제어를 관리합니다.
설정 변경은 일반적으로 신규 작업부터 반영됩니다.

### 4-1. Whisper 모델(STT) 선택 기준

UI 옵션 예: `large-v3-turbo`, `large`, `medium`, `base`

| 모델 | 품질 경향 | 속도/자원 사용 | 권장 사양 |
| --- | --- | --- | --- |
| `base` | 기본 | 빠름/낮음 | 저사양 CPU 환경 |
| `medium` | 중간 | 중간 | 일반 데스크톱 |
| `large` | 높음 | 느림/높음 | 고사양 CPU/GPU |
| `large-v3-turbo` | 높음(최적화형) | 비교적 빠름/높음 | 고성능 환경, 처리량 우선 |

선택 절차:
1. SettingsDialog에서 STT 모델 항목을 엽니다.
2. 시스템 사양에 맞는 모델을 선택합니다.
3. 저장 후 1~2분 분량 샘플 오디오로 지연시간과 정확도를 점검합니다.

### 4-2. LLM Provider 선택 (`ollama` / `llamacpp`)

1. SettingsDialog의 **LLM Provider** 항목에서 `ollama` 또는 `llamacpp`를 선택합니다.
2. 선택한 Provider가 로컬에서 실행 중인지 확인합니다.
3. Provider별 모델 목록이 로드되는지 확인합니다.

선택 기준:
- `ollama`: 운영/배포 편의성과 모델 관리 단순성이 필요한 경우.
- `llamacpp`: 직접 모델 파일/런타임 옵션을 세밀 제어해야 하는 경우.

### 4-3. 요약 및 임베딩 모델 매핑

1. 요약(Summary) 모델 선택 항목에서 `models/text/` 또는 Provider 목록의 모델을 지정합니다.
2. 임베딩(Embedding) 모델 선택 항목에서 `models/embed/` 또는 Provider 목록 모델을 지정합니다.
3. 저장 후 동일 문서로 검색 테스트를 실행해 결과 일관성을 확인합니다.

### 4-4. 다크 모드 및 서버 종료(Shutdown)

1. 테마 토글에서 **Dark Mode**를 선택/해제합니다.
2. 좌측 하단 **종료(Shutdown)** 버튼의 의미를 확인한 뒤 사용합니다.

중요 경고:
- **종료 버튼은 단순 UI 창 닫기가 아닙니다.**
- **RecordRoute 서버 전체(오케스트레이터 및 엔진 프로세스)를 종료하는 파괴적 액션입니다.**
- 실행 중 작업은 중단될 수 있으므로, 운영 중에는 승인 절차 후 사용하십시오.

### 주의사항 및 검증 방법

- 설정을 한 번에 여러 개 바꾸지 말고 항목별로 분리 적용합니다.
- Provider 변경 후 모델 목록이 비어 있으면 서버/엔진 상태를 먼저 점검합니다.
- 검증 기준:
  - 저장 후 설정 유지.
  - 변경 설정으로 신규 작업 성공.

## 모델 선택 가이드 및 공통 주의사항

### 모델 선택 요약

- STT 정확도 우선: `large` 또는 `large-v3-turbo`.
- 자원 제약 우선: `base` + LLM `Q4_K_M`.
- 균형형 기본값: STT `medium` + LLM `Q5_K_M`.

### 운영 주의사항

- 모델 교체 전 현재 사용 모델 파일과 설정값을 백업해 롤백 경로를 확보합니다.
- 대규모 모델 적용 전 파일 무결성(크기/해시)과 디스크 여유 공간을 점검합니다.
- 장애 보고 시 필수 정보: Job ID, 모델명, 양자화 레벨, Provider, 오류 시각.

### 사용자 검증 시나리오

1. 사전 준비 검증: 모델 다운로드/배치 후 SettingsDialog 목록 노출 확인.
2. 처리 검증: 오디오 업로드 후 `completed` 결과와 요약 확인.
3. 탐색 검증: 검색 실행 후 SimilarityGraph 노드 이동으로 연관 문서 확인.
