# RecordRoute Rust 전환 WBS

이 문서는 `docs/rust-cpp-backend-rewrite-plan.md`를 실행 단위로 분해한 **Work Breakdown Structure(WBS)** 입니다.

- 기준 문서: `docs/rust-cpp-backend-rewrite-plan.md`
- 범위: Rust 오케스트레이터 + C++ 엔진(독립 프로세스) 전환
- 비범위: `deprecated/`를 기본 실행 타깃으로 삼는 신규 기능 개발

## 0. 마일스톤 개요

| 마일스톤 | 목표 | 종료 기준(DoD) |
|---|---|---|
| M0 | 계약/운영 기준선 고정 | API/에러 계약 문서화 + 검증 체크리스트 확정 |
| M1 | Rust 오케스트레이터 골격 구축 | 헬스체크/타임아웃/재시작/배압 기본 동작 |
| M2 | 엔진 분리/연동 안정화 | 엔진별 큐 분리 + 내부 HTTP 계약 연동 |
| M3 | read-heavy 경로 이관 | 검색/조회 경로 성능·정합성 기준 충족 |
| M4 | `/process` 전환 Go/No-Go | 게이트 기준 충족 시 단계적 전환 승인 |

## 2. RACI(권장)

| 영역 | Responsible | Accountable | Consulted | Informed |
|---|---|---|---|---|
| API 계약 | 백엔드 | 백엔드 리드 | 프론트엔드, QA | 운영 |
| 오케스트레이터 운영성 | 백엔드 | 플랫폼/백엔드 리드 | SRE | 전 팀 |
| 엔진 연동 | 백엔드 | 백엔드 리드 | C++ 엔진 담당 | 운영 |
| 성능 검증 | 백엔드/QA | 백엔드 리드 | SRE | 전 팀 |
| `/process` Go/No-Go | 백엔드+운영 | 제품/기술 리드 | QA, 프론트엔드 | 전 팀 |

## 3. 리스크/대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 계약 불일치 | 클라이언트 장애 | 계약 테스트 선행 + 회귀 자동화 |
| 단일 큐 병목 | 지연 급증 | 엔진별 큐/동시성 분리 강제 |
| 엔진 프로세스 불안정 | 장애 전파 | 헬스체크/자동 재시작/서킷브레이커 |
| 오디오 품질 편차 | STT 품질 저하 | `symphonia` 변환 검증 셋 구축 |

## 4. 추적 규칙

- WBS 상태는 `Not Started / In Progress / Blocked / Done` 4단계로 관리합니다.
- 주간 점검 시 각 WBS 항목에 대해 **진행률, 블로커, 다음 액션**을 업데이트합니다.
- M4 이전에는 `/process` 전면 전환 완료로 문서화하지 않습니다.
