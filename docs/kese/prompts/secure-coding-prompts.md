# RecordRoute용 시큐어 코딩 프롬프트 묶음

이 문서는 현재 저장소의 기술 경계를 기준으로 바로 복사해 사용할 수 있는 프롬프트 모음입니다.

## 1. Rust/axum API 엔드포인트 구현

```markdown
RecordRoute 저장소 기준으로 Rust/axum API 엔드포인트를 구현해주세요.

필수 보안 요구사항:
- 인증/인가가 필요한 엔드포인트인지 먼저 판단하고, 필요하면 인증 누락 상태를 그대로 두지 말고 명시적으로 설계안을 포함할 것
- 입력값은 타입, 길이, 형식, 범위를 검증할 것
- 파일명, transcript_id, query 파라미터는 `..`, 절대경로, 역슬래시 같은 경로 조작 문자를 허용하지 말 것
- 내부 저장 경로, 절대 파일 경로, 민감한 환경 변수 값을 API 응답에 노출하지 말 것
- 에러 메시지는 사용자용과 내부용을 구분하고, 내부 구현 세부사항은 일반 응답에 노출하지 말 것
- DB/스토리지 접근은 최소 권한 원칙을 따를 것
- 기존 `app/*` 공용 로직과 HTTP 핸들러의 경계를 유지할 것

출력 형식:
1. 위협 모델 요약
2. 구현 코드
3. 검증 포인트
4. 남은 보안 리스크
```

## 2. 파일 업로드/다운로드 처리

```markdown
RecordRoute의 파일 업로드/다운로드 기능을 구현 또는 수정해주세요.

필수 보안 요구사항:
- 업로드 크기 제한을 명시하고 우회 불가하게 적용할 것
- multipart에서 허용 필드 이름과 개수를 명확히 제한할 것
- 빈 파일 업로드를 거부할 것
- 업로드는 임시 경로에 저장 후 publish/cleanup 흐름을 유지할 것
- 다운로드는 logical file name만 허용하고 `..`, 절대경로, 역슬래시를 차단할 것
- summary/stt/audio artifact를 혼동하지 않도록 타입별 분기와 존재 검증을 넣을 것
- 내부 storage key나 절대 경로를 API 응답에 노출하지 말 것

출력 형식:
1. 취약점 후보 목록
2. 안전한 구현 코드
3. 테스트 케이스
```

## 3. SQLite/PostgreSQL 데이터 접근

```markdown
RecordRoute 저장소 기준으로 SQLite/PostgreSQL 데이터 접근 코드를 구현해주세요.

필수 보안 요구사항:
- sql driver 전환(sqlite/postgres)이 있어도 동작/권한/트랜잭션 의미가 어긋나지 않게 할 것
- DB 접속 문자열과 비밀은 `.env` 외부화 전제를 유지할 것
- 절대 경로 대신 logical file name, storage key 같은 추상화된 식별자를 우선 사용할 것
- schema 변경 시 least privilege와 rollback 경로를 함께 제시할 것
- 로그에 raw connection string, token, path 같은 민감 정보를 남기지 말 것

출력 형식:
1. 설계 요약
2. 코드 또는 SQL
3. 권한/운영 주의사항
```

## 4. 외부 CLI 래핑

```markdown
RecordRoute처럼 ffmpeg, whisper-cli, llama-cli 같은 외부 CLI를 Rust에서 래핑하는 코드를 작성해주세요.

필수 보안 요구사항:
- shell 문자열 결합 대신 인자 배열 기반 실행을 사용할 것
- 종료 코드뿐 아니라 결과 파일 존재, stdout/stderr 형식 검증까지 고려할 것
- 부분 실패 시 임시 산출물을 cleanup 할 것
- 사용자 입력이 파일 경로나 인자로 들어갈 때 경계 검증을 수행할 것
- 외부 도구 실패 메시지는 운영 디버깅에 충분하되 민감 경로/토큰 노출은 피할 것
- 재시도와 fallback이 있으면 조건을 명확히 문서화할 것

출력 형식:
1. 실패 시나리오 목록
2. 안전한 실행 코드
3. 검증 로직
```

## 5. `.env`와 비밀 관리

```markdown
RecordRoute 저장소 기준으로 `.env`와 비밀 관리 구조를 개선해주세요.

필수 보안 요구사항:
- `.env`는 로컬 런타임 루트에서만 읽고 Git에 포함하지 않을 것
- `.env.example`에는 실제 비밀값을 넣지 말 것
- 토큰, DB URL, 외부 모델 접근 자격 증명은 로그와 에러 응답에 노출하지 말 것
- 운영/개발 환경별로 필요한 변수와 기본값, 필수값을 구분할 것
- 민감 설정 변경 시 후속 검증 항목을 함께 제시할 것

출력 형식:
1. 변수 분류표
2. 개선안
3. 검증 체크리스트
```

## 6. 에러 처리와 로깅

```markdown
RecordRoute 저장소 기준으로 에러 처리와 로깅을 보안적으로 정리해주세요.

필수 보안 요구사항:
- 사용자 응답에는 내부 파일 경로, stack trace, raw stderr를 그대로 노출하지 말 것
- 운영 로그에는 어떤 요청이 실패했고 어떤 stage에서 실패했는지 추적 가능해야 할 것
- 업로드, 다운로드, 모델 준비, queue 실행 같은 민감 동작은 감사 가능한 이벤트로 남길 것
- 로그와 메트릭에 토큰, DB URL, 절대 경로, 원문 transcript를 무분별하게 남기지 말 것
- CLI 래핑 실패는 종료 코드, 핵심 원인, retry/fallback 여부를 분리해 기록할 것

출력 형식:
1. 현재 리스크 요약
2. 개선 코드 또는 설계안
3. 운영 로그 예시
```
